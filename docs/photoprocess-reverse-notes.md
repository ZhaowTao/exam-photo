# PhotoProcess.exe 逆向笔记

> 记录 2026-10 分析人社部人事考试中心「照片处理工具」的过程与结论。
> 目的只有一个：搞清楚它**到底做了什么校验**，好在非 Windows 系统上产出等价文件。

## 1. 样本

| 项目 | 值 |
|---|---|
| 文件名 | `照片处理工具.exe` |
| 体积 | 约 5 MB |
| 类型 | PE32 executable (GUI), Intel 80386, 32-bit |
| 加壳 | 无。PE 头完整，导入表可读，节区名正常 |
| 编译器痕迹 | MFC42（VS6 时代）、OpenCV 1.0 |
| 版本资源 `FileVersion` | `1.0.0.25` |
| 版本资源 `CompanyName` | 人社部人事考试中心 |
| 附带文件 | `photo.ini`、`使用说明.doc`、`opencv` 相关 DLL |

无壳这一点很关键：不需要脱壳，字符串和导入表直接可读，分析成本从「几天」降到「一小时」。

## 2. 关键字符串

从 `.rdata` 段直接读出的、决定行为的字符串：

```
photo.ini
min_width
min_height
width
height
haarcascade_frontalface_alt2.xml
cvLoadImage
cvResize
cvSaveImage
报名照片.JPG
背景必须是白底或蓝底
```

`haarcascade_frontalface_alt2.xml` 说明人脸检测用的是 OpenCV 自带的 alt2 级联，不是自训练模型。这决定了它的能力边界：正脸检出率高，侧脸、遮挡、过度美颜会漏检。

## 3. 参数（photo.ini）

```ini
[photo]
min_width  = 295
min_height = 413
width      = 295
height     = 413
```

`min_*` 是输入门槛，`width/height` 是输出尺寸。两者数值相同，意味着一件事：**输入不能小于输出**，即官方明确禁止把低像素照片放大使用（《使用说明.doc》里也写了这句话）。

## 4. 处理流程

```
读 photo.ini
  ↓
cvLoadImage(用户选择的图)
  ↓
if (w < 295 || h < 413) → 弹窗拒绝，流程终止
  ↓
Haar 检测：人脸数量 != 1 → 弹窗拒绝
  ↓
底色判定：白底 or 蓝底，否则拒绝
  ↓
cvResize(295, 413)
  ↓
cvSaveImage(报名照片.JPG, quality ≈ 75)
```

几个细节：

- **不做裁剪**。它是直接 `cvResize` 拉伸到 295×413，所以原图比例不对时人脸会被压扁。本项目的 `crop_to_ratio` 先按比例居中裁剪再缩放，输出更自然——这是有意的改进，不是遗漏。
- **不做美化**。没有任何磨皮、提亮、美白代码路径。
- **固定输出文件名** `报名照片.JPG`（大写扩展名，Windows 不敏感）。

## 5. 输出文件特征

用工具处理若干张图后比对输出：

| 特征 | 值 |
|---|---|
| 尺寸 | 恒定 295×413 |
| 格式 | baseline JPEG（SOF0） |
| 体积 | 8–11 KB，随内容浮动 |
| EXIF | 无 |
| ICC | 无 |
| 渐进式 | 否 |
| 数字签名 / 水印 / 隐写 | **无** |

最后一行是整个分析里最有价值的结论：**输出文件里没有任何可以标识「这是官方工具生成的」的东西**。

## 6. 服务端到底校验什么

结合多个报名系统的前端提示和实际上传行为，服务端只做四类校验：

1. 扩展名 / MIME 是否为 jpg
2. 宽高是否等于规定值
3. 体积是否在区间内
4. 底色抽样是否符合要求

没有签名校验，没有隐写检测。所以只要产出满足这四项的 baseline JPEG，在服务端视角与官方工具输出等价。

这也解释了一个常见现象：用 PS 按规格存一张图，同样能过。官方工具的真正作用是**替不会用 PS 的人把四件事做对**，而不是防伪。

## 7. 为什么本项目不照抄 cvResize

官方直接拉伸，遇到 4:3 或 16:9 的原图会把人脸压扁。虽然能过机器校验，但审核人员肉眼看到变形照片观感很差。

本项目改成：按目标比例居中裁剪（顶部多留 28% 余量给头部）→ LANCZOS 缩放。输出同样 295×413，但不变形。

## 8. 局限与未验证项

- **人脸检测没有复刻**。Haar 级联需要 OpenCV，装包体积 100 MB+，为一个布尔判断不值得。本项目改用「中部纹理 vs 边缘纹理」的启发式，只能发现纯色块这种明显错误。若官网以「未检测到人脸」驳回，只能换照片。
- **底色判定是抽样，不是全图**。取四角 12% 区域的中位色，对纯色背景准确，对渐变背景会误判。
- **不同省份的 exe 可能参数不同**。本例是国考/人社部版本（295×413）。部分省考、行业考试用 413×579、480×640 等，参数在各自的 `photo.ini` 里，本项目用 `--size` 覆盖即可，但没有逐一验证过。
